> 耗时单位 μs；提升率 = (Base − 优化) / Base，**正提升率表示耗时下降（更快）**。

## 二、字段含义

| 字段 | 含义 |
|---|---|
| BS | 批次大小（batch size），每表覆盖 1/2/4/8/16/32/48/64/96/128/192/256 共 12 档 |
| H | Hidden 维（DeepSeek=7168，K3=3584） |
| TOPK | 每 token 激活专家数 |
| Moe_num / E | MoE 专家总数 |
| S | 共享专家数（MegaMoE 表均为 0） |
| Intermediate | FFN 中间层维度（仅 EP8 表） |
| Tokens | 单次输入 token 数（仅 EP8 表） |
| Dispatch / Combine | DeepEP 两个算子：路由分发 / 结果合并 |
| dtype | Dispatch 通常 FP8（K3 EP32 为 BF16 例外）、Combine 均为 BF16；MegaMoE 系列为 W4A8 |
| Base / 优化 | 对比基线版本 / 本次待评估的 DeepEP 优化版本 |
| MFU（带/不带空泡）、掩盖率、dispatch/combine 带宽 | 仅 MegaMoE EP64/128 的 BS=96 行附带 |

## 五、数据要点与异常提醒

- 提升率规律：**A 组 DeepSeek**（尤其 EP64+）优化版普遍更快（正值多）；**C/E 组 MegaMoE** 小 BS 档优化版反而明显更慢（负提升率），BS≥48/96 后转正——小批次下 DeepEP 优化收益不明显。
- 多处标注「环境配置：待填写」「版本/HDK/RXDMA参数/日志链接：待填」。
- 数据缺失/异常：A1 表 G 列 3 个异常值（-376/-402/-1778）；B2 Dispatch 256 档、B3/B4 部分 256 档缺失。
